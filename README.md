# dsh-memory-nian

给 [DeepSeek Harness](https://github.com/deepseek-ai) 用的自托管记忆插件。

## 它解决什么

模型每次开新对话都是白纸——昨天定的方案、前天踩过的坑、上个月说过的偏好，
一概不记得，每次都要重新讲一遍。

这个插件把那些东西存进本机一个 SQLite 文件：新对话开始时自动带进上下文，
聊到相关话题时再把对应条目捞出来。**数据不上传任何服务器**，全程离线可用。

## 三个设计选择

**① 按作用域分层，不按长短分**

核心（跨项目通用的身份、偏好、原则、禁令）→ 项目（这个项目是什么）→
分支（进行中的决策、现状、待办）→ 细节（事实、教训、专题、规程）。

好处是写的时候不用纠结「这条算知识还是算教训」——看它成立的范围有多大就行。
下面有完整的分类表。

**② 中文优先的检索**

CJK bigram 切分 + BM25 打分，额外叠一层拼音和首字母：
「人工智能」写成「人工作站能」也能搜到，`ctgzt` 这种缩写也能。

**③ 零运行时依赖**

只用 Node 自带的 `node:sqlite`（**Node 23.4 起免标志位**；DSH 自带的运行时是 Node 24，
装进 DSH 直接可用）。仓库里的拼音库是**可选增强**，删掉插件照样跑，
只失去同音错字和首字母缩写这两层容错，字面检索不受影响。

## 四层结构

按**作用域从大到小**分四层，每层带一个 `category` 做层内分类。

| 层 | 装什么 | category |
|---|---|---|
| `core` | 跨项目通用：身份、偏好、原则、禁令 | `identity` / `preference` / `principle` / `rule` |
| `project` | 项目的静态画像 | `overview` / `structure` / `features` / `history` |
| `branch` | 项目里进行中的事，会过时会变 | `decision` / `ops` / `todo` / `quote` |
| `detail` | 最小颗粒的积累 | `fact` / `lesson` / `topic` / `procedure` / `impl` |

`project` 层的两个新子类是分工的关键：

- `features` —— **这个项目有哪些功能 / 各自的边界**。改代码之前先看它，否则会把两个功能合成一个、或者重造已经有的轮子。
- `history` —— **历史年表**：什么时候、按什么顺序变成现在这样。**只记变化点**，不记现状（现状归 `features`）、不记机制（机制归 `impl`）。判据是「删掉时间就不成立」的才归它。每一行都指向一条 `detail` 条目，年表自己不带正文。
- `impl`（在 `detail` 层）—— **某个功能怎么实现的、当初为什么这么定**。可以很长，需要时再搜。

`detail` 的四种最容易被问「这条到底放哪个」：

- `fact` —— 一句话的客观事实（版本号、路径、端口）
- `lesson` —— 现象 + 原因 + 做法。**中文记忆的默认形态**：踩过的坑、摸到的规律都放这
- `topic` —— 一个完整的小专题，可到 3000 字（机制 + 判据 + 反例）
- `procedure` —— 能照着执行的**操作规程**：步骤 + 命令 + 检查清单

`topic` 回答「为什么会这样」，`procedure` 回答「我该按什么顺序做」。
出现「这件事又是零零散散几条、拼不出完整流程」的时候，就是缺 `procedure`。

> 东西废掉或换代了**不要删**：旧条目标成「留档」并写明「⛔ 已停用 / 已被 vN 取代」。
> 删了就没人知道它曾经存在，后来的人会以为这功能还在。

每层还有一张 `<层>_hist` 版本表：`memory_update` 改动内容之前，
插件会先把旧值整条写进去（不是靠数据库触发器），所以版本历史一定和实际改动同步。

## 十四个工具

| 工具 | 用途 |
|---|---|
| `memory_search` | 关键词检索；可按层 / 项目 / **分类** / 状态 / 时间段过滤，按相关度降序。**搜不到会直说**，不给你一份像模像样的假清单 |
| `memory_read` | 按 id 读一条完整内容与元数据（读一次算一次「用过」） |
| `memory_remember` | 写一条新记忆。写入前自动查重，近邻会给提示 |
| `memory_update` | 改内容 / 关键词 / 状态 / 归属 / 发生时间 / 情境 / 情绪；改前自动留快照 |
| **`memory_forget`** | **删一条**。默认只归档（随时能找回来），传 `hard=true` 才物理删除，且删除前仍留快照 |
| `memory_project` | 取某个项目的全部记忆，按子类分组 |
| **`memory_project_core`** | **读写项目核心 Markdown**（每个项目一份，按关键词注入）。写入会返回字数与上限，超了当场说「超多少、注入会被截断」 |
| **`memory_plan`** | **方案与任务清单**：把「要做什么、分几步」存进库，做完勾一项。压缩压不掉，换会话也捞得回 |
| **`memory_conflict`** | **冲突治理**：找「同一个位置填了不同值」的说法，给留新 / 留旧 / 都留三种处理 |
| `memory_recent` | 最近写入 / 更新了哪些 |
| `memory_dream` | 最近 N 天有改动的条目，用来判断哪些该合并（只报告，不改数据） |
| **`memory_timeline`** | **看一条记忆被改过几次、每次改了什么**；支持**还原到某一版**（还原本身也可撤销） |
| **`memory_health`** | **库体检**：没关键词 / 超长 / 沉底 / 归属异常 / 项目名重复。每类都附「具体怎么修」 |
| **`memory_export`** | **导成 Markdown 文件**，可读、能进 git、能给别的 AI 用 |

每个工具的描述都写清了「什么时候该用它」——模型靠这个选工具，
所以描述不是装饰，是功能的一部分。

> `memory_core`（编辑常驻 MEMORY.md）**默认不注册**：官方 `dsh-core-memory` 已提供同名工具。
> 想让记忆功能完全自足，把配置 `coreTool` 设 `true` 并先禁用 `dsh-core-memory`，否则同名注册会失败。

## 方案与任务清单

`memory_plan`：把「要做什么、分几步」存进**记忆库**，做完一项勾一项。

为什么不是存聊天记录里：上下文压缩会把早期对话折成摘要，而**记忆库不会被压没**，
换个会话也捞得回来。首轮注入时只带一行「进度 + 下一步」，不占注入预算。

```
memory_plan action=create  title=仓库重构  content="- [ ] 改数据层

- [ ] 改前端"
memory_plan action=check   item=改数据层   note=顺手把索引也换了
```

勾选的判据是**唯一匹配** —— 含糊就报错，不赌某个候选。
勾上时可以顺手记一句「怎么实现的」，全勾完收档时直接变成素材。

## 冲突治理

写入时把两件事分开处理：

- **重复**（说同一件事）→ 拦下，建议把新信息合进那条
- **冲突**（同一个位置填了不同的值）→ **照常写入**，但明确告诉你哪里矛盾

判据是「同一个槽位填了不相交的值」：端口、版本号、百分比。
**路径不参与判定** —— 不同记录说不同文件是常态，实测扫出来的全是误报。
也不按相似度区间判重复：改一个端口，相似度照样 0.9 以上。

`memory_conflict` 三个动作：`scan`（找候选）/ `show`（看双方原文）/ `resolve`（留新 / 留旧 / 都留）。

## 删除与恢复

「不用了」有三档，别混：

| 动作 | 怎么调 | 还能搜到吗 | 能恢复吗 |
|---|---|---|---|
| 完结留档 | `memory_update(status="stale")` | 能（默认检索就包含） | — |
| **归档** | `memory_forget(id)` | 默认不能；`status="archived"` 能 | 能，改回 `status="active"` |
| **物理删除** | `memory_forget(id, hard=true)` | 不能 | 删除前留了快照，`memory_timeline` 还能查出它长什么样 |

「删了怕以后想不起来」就用默认的归档，别用 `hard`。

## 版本历史与时间线

每次 `memory_update` 真正改了内容（标题/正文/关键词/状态/重要性/归属），
都会把**改前的完整快照**写进 `<层>_hist` 表，然后 `memory_timeline` 就能回看：

```
memory_timeline id=<前12位>
① 2026-11-12 10:00  最初版本
② 2026-11-12 11:00  改了：content, importance
   content: 「原来那句」→「新写的那句」
③ 2026-11-12 12:00（当前）  改了：status
```

`hit_count`、`last_accessed_at`、`updated_at` 这几个字段**不记历史** ——
它们每读一次就变，记进去会把历史表刷爆，而且没有追溯价值。

想退回某一版：`memory_timeline id=... action=restore version=N`。
还原前会把**当前**版本也存一份快照，所以还原本身可以再撤销。


## 三条注入路径

| 路径 | 什么时候 | 注入什么 |
|---|---|---|
| 首轮快照 | 新对话的第一条消息之前 | 核心层的身份 + 偏好 + 原则与禁令(重要性≥2) + 项目清单 |
| 每条命中 | 每条 ≥4 字符的用户消息 | 细节层里按关键词打分取 top-N |
| **压缩后重注入** | 上下文被压成摘要之后 | 长期记忆快照再灌一遍（同一次压缩只灌一次） |

最后一条是专门对付「压缩完就忘事」的：压缩把整段历史折成摘要，
压缩前读过什么、定过什么结论都不在摘要里了，所以压缩后的第一步先把记忆补回去。

另外还有一条提醒：**距上次写记忆已经过了若干轮、且当前在调工具干活**时，
会投一句「这轮有没有值得长期记的」。纯聊天、刚写过、冷却期内都不吭声。

## 项目核心（按项目注入专属规则）

前面那三层记忆都是**不分场合**的：首轮快照全量灌、每条消息按关键词捞。但有些东西是
「做这个项目时不知道就会做错、换个项目完全用不上」的 —— 比如某个工具特有的操作顺序、
某个项目踩过的坑。

塞进核心层 ⇒ 每个会话都背着它，纯粹占地方；塞进细节层 ⇒ 检索不到，因为
你不会主动去搜"我可能踩什么坑"。所以单独做一层：**每个项目一份 Markdown，
只在当前对话真的在做那个项目时才注入。**

### 怎么判断"在做哪个项目"

按**关键词**匹配你这句话，命中就挂上；连续几轮不提就自动摘掉（默认能扛 4 轮）。
判据刻意用**轮次**而不是时间 —— 去泡碗面回来还在干同一件事，按时间算就误摘了。

挂上之后有节流：同一个项目在一个会话里只注入一次，因为内容已经在对话历史里了，
每轮再灌一遍纯属烧 token。

### 目录结构

```
<workspace>/_项目核心/
├── projects.json      # 项目清单：关键词、联动、父子关系、文件名
├── 我的项目.md         # 每个项目一份，只写"不看就会踩错"的东西
└── ...
```

`projects.json`：

```json
{
  "projects": {
    "我的项目": {
      "file": "我的项目.md",
      "keywords": ["项目名", "那个缩写", "特有名词"],
      "linked": [],
      "parent": ""
    }
  },
  "maxMiss": 3,
  "maxCharsPerProject": 1500
}
```

| 字段 | 作用 |
|---|---|
| `keywords` | 命中任一就把这个项目挂上，大小写不敏感 |
| `linked` | 联动：挂上 A 也带上 B |
| `parent` | 父子：挂上父项目时子项目一起挂 |
| `maxMiss` | 连续几轮不提就摘掉。注意代码判的是 `> maxMiss`，所以实际能扛 `maxMiss + 1` 轮 |
| `maxCharsPerProject` | 单个项目正文的注入上限，超了截断 |

### 侧栏面板

装了之后侧栏多一个 🧠 面板，能看见每个项目当前的状态：

```
已加载 1
  [✓] 我的项目        1200 字   余 4 轮      ← 还活跃，再 4 轮不提就自己掉下去
未加载 2
  [ ] 另一个项目       800 字   已注入过      ← 掉了，但正文还在这次对话的历史里
  [ ] 还没用过的项目   没写文件                ← 一次都没注入过
```

每行只有**两种状态**，点一下在它们之间翻：

- **🔒 锁住** —— 把"现在在不在上面"固定下来：在上面就永远在上面（不会因为没提到而回落），
  在下面就永远在下面（提到关键词也不来）。

- **🔓 开着** —— 跟关键词走，该挂挂、该掉掉。

锁定**按窗口存**：A 窗口锁住"我的项目"不影响 B 窗口。

面板每 8 秒静默刷一次，所以那个「余 N 轮」会自己往下走。

### 第一次用怎么建

不用手写。跟模型说一句「帮我把这个项目的规矩沉成项目核心」，它会自己建条目和 `.md`；
或者在面板里点「＋新建」，填项目名和关键词。

**只写"不知道就会做错"的东西** —— 背景介绍、历史、代码说明都别往里放，
每多 1000 字，每次注入就多花 1000 字的 token。

## 和上下文压缩配合

插件**不实现压缩**（那是 DSH 的 `/compact`），但它把压缩前后的两步接上了，靠三个钩子。

**① 落档催办（`agent/pre-step`）**

上下文水位到 `remindTokens`（读 `~/.dsh/auto-checkpoint.json`）时，在模型生成**之前**插一条提醒，
让你先写 `precompact-<session>.md`。走预发（直接进上下文），不弹确认框，不占你一次点击。

拿不到 `agent.session` 时退回轮次判据：每 `precompactEveryTurns` 轮查一次落档新鲜度，
超过 `precompactFreshMs` 没更新就算旧。这样功能不至于哑掉。

**② 落档写完，自己按冲水键（`agent/turn-stopping`）**

同时满足四个条件才压：

- token 超过 `remindTokens`
- 工作区里有 `precompact-*.md`，且是 `precompactJustWrittenMs` 内写的
- 那份落档里有「🔑 这一轮定下的结论」这一节，且不是空的
- 同一份落档没压过

然后开一个后台任务，等 agent 空闲再调 `/compact`。不能在 `turn-stopping` 里直接调——
那时 agent 还没转 idle，会报 `Compaction is unavailable because this process has an active compaction, or the agent is not idle`。
压失败会把标记清掉，允许下次重试。

**③ 压缩完，把记忆再灌一遍（`agent/pre-step`）**

压缩完 DSH 会插一条 `source.kind === 'compact-checkpoint'` 的用户消息，里面带 `compactionId`。
这是 pre-step 里**唯一**能判断「刚压过」的信号。同一个 id 只补注入一次，避免连续几步反复灌。

## 检索为什么对中文友好

- **字面**：CJK bigram 切分（`unicode61` 分词器对中文基本不可用），BM25 打分，
  `k1=1.5` / `b=0.75`。

- **拼音层**：查询和文档都额外生成拼音整串 + 拼音 2-gram。
  所以同音错别字（把「人工智能」写成「人工作站能」）也能命中。

- **首字母层**：2~14 个纯字母的查询额外走独立通道（`ctgzt` 这种缩写）。
  这一层单独加分而不混进主 BM25 —— 否则 `ct`/`tg` 这类满屏的二字组会把真命中淹掉。

- **时间衰减**：`importance < 3` 且非高分命中时按新旧降权；
  高分或高重要性的条目不衰减。

- **命中计数**：`hit_count` 只用于**同分时的平局决胜**，不乘进分数 ——
  避免"被搜到过 → 分更高 → 更容易被搜到"的正反馈。

## 写入时的两道提示

不是"自动合并"，是**告诉调用方发生了什么**：

- **重复**（内容重合 ≥ 65%，Jaccard）：不写，返回已有条目的 id，
  让你决定是用 `memory_update` 合并、还是加 `force: true` 另立。

- **近邻**（重合 30%~65%）：**照写**，但附一句提醒
  ——「这条与 XX 有 47% 重合」。记忆会演化（先说 A、后来改成 B），
  这种情况既不该硬拦，也不该让两条互相打脸的记录悄悄并存。

## 安装

### 方式一：DSH 直接装目录（推荐，不需要 npm 账号）

1. 本页右上角 **Code → Download ZIP**，或者直接  本仓库
2. 解压到任意目录（例如 `<你的插件目录>/dsh-memory`）
3. 打开 DSH → **插件** → **添加插件** → 选那个目录
4. 重启 DSH

不需要 Node、不需要 npm、不需要命令行。

### 方式二：npm（包名 `dsh-memory-nian`）

```bash
dsh plugin add dsh-memory-nian --profile <your-profile>
```

> 注意：这个包**还没发布到 npm**（`dsh-memory` 那个名字已被别人占用）。
> 在它上线之前请用方式一。

装完都重启 DSH。插件自带 `cordis.patch.yml`（`dsh.bundle.patch`），会自动 insert 插件行。

**第一次运行不需要任何准备**：库文件不存在时会自动建表（13 张表 + 15 个索引），
直接就能写。已有旧库也能直接用 —— 同一套 `IF NOT EXISTS` 语句会只补缺的表，不碰数据。

## ⚠️ 插件冲突（装之前先看这段）

DSH 拒绝**同名工具**注册，而且失败是**静默**的 —— 表现是「插件装上了，但工具不见了」。
所以装之前确认没有别的记忆插件占着 `memory_*` 这组名字：

| 冲突源 | 症状 | 处理 |
|---|---|---|
| 别的记忆插件 | 它注册同名的 `memory_search/read/remember/...`，谁先加载谁赢 | 禁用那个插件，或给本插件设 `toolPrefix` |
| `dsh-core-memory` | 它提供 `memory_core`；本插件默认不抢这个名字 | 想完全自足时：禁用它 + `coreTool: true` |
| 其它自写插件 | 同样看名字 | 看日志 |

本插件在注册失败时会**明确打出警告**（红字级别的 `logger.warn`），写明哪些工具没注册上
和两种解法，不会闷声不响：

```
[dsh-memory] ⚠️ 2 个工具没注册成功，几乎都是名字被别的插件占了：

  - memory_search（tool memory_search already registered）
  - memory_remember（...）
  解法一：禁用占名的那个插件（它也注册同名 memory_*）；
  解法二：在本插件配置里设 toolPrefix（例如 "ext_"），工具就会叫 ext_memory_search。
```

## 数据与隐私

- 全部数据在 `<workspace>/.dsh-memory/memory.db`，纯本地 SQLite。
- 插件不做任何网络请求。
- 备份就复制这个 `.db` 文件；建议用 SQLite 的 backup API 而不是直接 copy
  （开了 WAL 时直接复制可能漏掉未 checkpoint 的数据）。

- **删除是分档的，说清楚**：`memory_forget` 默认只把状态标成 `archived`（数据仍在库里，
  随时能恢复）；只有 `hard=true` 才真正删行，而且删除前的快照仍留在版本表 `*_hist` 里。
  真想彻底抹掉，得连库文件一起处理。

## 从别的记忆插件迁过来

数据格式的权威定义就是 `lib/schema.js` 里的建表语句 —— 四张表、每张表的 `category` 取值都在注释里。

做法：写个脚本读旧库，逐条判断该归哪一层哪一类，写进新库。注意三点：

1. **中文记忆通常是「现象+原因+做法」三段一体的**，不要试图把一条拆成「知识」和「教训」，拆不开的；
2. **核心层只放跨项目通用的东西**（身份/偏好/原则/禁令），项目技法一律下沉到 `detail` 并带 `project`；
3. **正文写提炼后的祈使句，别抄原话** —— 原话里的语气词和当时的情绪会每次注入都占位置。
   原话要留就单独存一条 `branch` + `category: quote`。

### 0.6.1（2026-11-21）

**能导入了、体检能一键修了、项目能合并了**

**① `memory_import`：把另一个记忆库合并进来**（第 18 个工具）

换机器、恢复备份、两台机器同步都用它。**合并的是另一个 `memory.db`，不是导入导出的 Markdown** —— 正文里完全可能出现 `###`、`> id:` 这类行，反向解析迟早就错位，而且一错就是静默错（导进去的内容跟标题对不上，还查不出来）。`.db` 是结构化的，id / 时间 / 关键词 / 状态 / `hit_count` 全部原样搬。

三个保护：
- **默认 `dry_run` 只预演**：先报「会新增 N 条、覆盖 M 条、跳过 K 条」，确认后再传 `dry_run: false`。方向搞反（拿旧备份盖新库）是不可逆的。
- **同 id 默认 `skip`**，保留目标库原样；要覆盖传 `mode: 'overwrite'`，且只覆盖两边都有的列。
- **列交集**：源库可能是老 schema（少 `happened_at`/`domain` 那批后加的列），按名字取交集、缺的列落默认值。用 `SELECT *` 按位置插会整列错位。

**② `memory_health` 能一键修了**（`fix: true`）

只修**两类无损**的：`project` 每段去首尾空格、`project` 是空串的改成「全局」。

**只动 `project` 一个字段**，`content`、`updated_at`、`happened_at` 全不碰。`updated_at` 尤其不能动 —— 这是规范化不是内容修改，动了「最近更新」排序和「沉底」判断全失真（体检刚修完就再也看不到哪些条目沉底了）。

想顺手补 `happened_at` 的念头被测试否掉了：它为 NULL 的语义本来就是「没特别说明，用记录时间」，补 `created_at` 不增加任何信息量，反而把「这条从来没填过事件时间」这个信号抹掉；而且真库上一跑会一次改两千多条。

**超长 / 没关键词 / 沉底照样只报告** —— 那三样要理解内容才知道怎么改，机器替你决定就是添乱。

**③ 项目能合并了**（面板项目行多了个「并」）

`from` 并入 `to`，跟「删除」不一样：**记忆归属是改过去、不是清掉**。关键词、父/关联关系一并并过去，正文文件留底成 `.merged`。

正文两种处理：
- **追加**（默认）：`from` 的正文追到 `to` 后面加分隔线
- **只留底**：不追加。为什么留这个 —— 两个项目的正文常常是不同角度写的（一个写「现在有什么功能」，一个写「踩过哪些坑」），硬拼在一起会变成两套互相打架的规范。

合并后超 `maxCharsPerProject` **只警告、不截断**（截掉的是你自己写的内容，而且你看不见少了哪段）。

**④ 一个容易忽略的去重**

一条记忆本来就同时属于 `from` 和 `to` 时（`甲,乙`），合并后不能变成 `甲,甲` —— 否则之后按项目查会重复命中同一条。

### 0.6.0（2026-11-21）

**项目能改名、能删、能挂多个父 —— 外加一次「提示词和实现对不上」的审计**

这一版不动数据结构和表，改的全是「项目核心」这一层的可用性。

**① 项目可以改名了。** 面板每行的「改」旁边多了「改名」。
改一次名字会连带改五处：清单里的 key、别的项目里对它的 `parent`/`linked` 引用、正文文件名、各窗口的锁定状态、记忆里写的归属项目（含 `父/子` 和逗号多值里的那一段）。
不做这一步的话，手改 `projects.json` 迟早会漏掉后四处 —— 表现是「项目还在，但挂不回原来的位置」。

**② 项目可以删了，而且会问你记忆怎么办。**
删项目 ≠ 删记忆，所以删除时让你三选一：

- **原样留着**（默认）：记忆还在，但项目没了，按项目名查不到它了
- **改成「全局」**：还搜得到，只是失去「它属于哪个项目」这层信息
- **标成完结留档**：检索仍能命中，只是标记成这件事完了

正文文件不删，改名成 `.deleted` 留底。

**③ 一个项目可以挂多个父。** `parent` 从字符串变成数组，同一个子项目能在 `父甲` 和 `父乙` 下面各出现一次，面板两边都显示。

**④ 父子层级不再限两层。** `父 → 子 → 孙` 可以一层层展开，面板按层级缩进。
⚠️ 层级是靠 `parent` 串起来的，**不是靠名字套娃** —— 新建项目时名字里不能带 `/`（它要变成文件名）。

**⑤ 项目核心正文上限 1500 → 2000**，默认常量和配置文件一起改了。

**⑥ 一次专门找「写了但没用上」的审计**，查出五处：

- 改名/删除只判 `Array.isArray(parent)` —— `parent` 是**字符串**的老数据被静默跳过，引用断掉却不报错
- 新建项目时父名写错会被**静默过滤**：项目建好了但没挂上，不缩进、不跟着父注入、全程没提示。现在直接报错并点名哪个父不存在
- `DEFAULT_MAX_CHARS` 没跟着配置一起调 —— 改了一个没改另一个，等于这条优化只对改过的机器生效
- 面板里 `child` 这个 class **从来没写过对应样式**，两级父子其实一直没有真缩进，只靠一个 `└` 符号凑合
- 5 处工具描述 + 1 处项目核心文档还写着「两级」—— 描述里写两级，模型就不会去用三级

**⑦ 顺手把「记忆该写多长」写进了工具描述**：`fact` ≤100 / `lesson` ≤300 / `topic`·`procedure`·`impl` ≤3000。
起因是实测发现上千条记忆里有 几百条超过 1200 字、其中 一批是 `lesson`。模型只看得到描述、看不到实现，描述里没写「该多短」，它就把所有细节都塞进去。

### 0.5.4（2026-11-20）

**记忆能分板块了，命中会按项目让位**

**① 两级子项目。** `project` 字段现在可以用 `/` 分父子：`父项目/子板块`、`父项目/另一个板块`。
查父（`父项目`）会带上所有子板块，查子只出自己那一块 —— **只向下覆盖，不向上**，
不然查一个板块会把整个项目全捞出来，等于没分。现有数据一条不用动，老名字照旧工作。

**② 命中按项目降权。** 以前注入只按关键词打分，命中的条目可能来自完全不相干的项目。
现在会看你这个窗口**已经激活了哪些项目核心**（`state.json` 里那个 `injected` 列表）：

- 属于活跃项目的 → 权重 1.0（子项目也算，`父项目/子板块` 挂在 `父项目` 名下）
- 其他项目 → 乘 `projectDownweight`（默认 **0.7**，配成 1 就是关掉）
- **没标项目的、以及「全局」条目 → 完全不动**

为什么按项目而不是按域：域是拿关键词猜「这轮在聊什么」，判错时该出现的记忆被压到 0.15 倍
还静默消失，代价太大；项目是写入时**明确标的**，不存在猜错。

三条护栏跟域降权一致：**只降权不硬拦**（条数不变，只挪排位）、没标项目的不参与、
**活跃列表为空时完全不降**（新会话还没注入任何项目核心，等于不知道这窗口在干什么，宁可不动）。

**③ 面板的父子树不再只认 `projects.json` 里的 `parent`** —— 名字里带 `/` 的会自动缩进挂到父项目下，
即使没手动声明过父子关系。

**内部**：新增 `readInjected(sessionId)`，带 id 归一化兜底 ——
完整 `session-xxx`、不带前缀、12 位尾三种格式都能读，避免换个 DSH 版本就静默失效。
另外 `debug.log` 里现在每轮都会打一行 `项目降权: N 条压到 ×0.7`，事后能核压掉了哪些。

### 0.5.0（2026-11-20）

**每条记忆都能翻回原话**

记忆是提炼过的话，细节早丢了。写的时候留了出处，但留了不等于能用 ——
现在新增 **`memory_source`**：给记忆 id（或直接给 `会话id#序号`），
它把那段对话的原话和前后几轮找回来。做年表、判断「这条结论是哪次定下来的」尤其有用。

**整批回滚**

一次大整理（比如全库回填某字段改了几千条）想整体撤回去，以前只能一条条来。
新增 **`memory_bake`**：把「上次固化之后动过的所有条目」存成一个快照，以后能整体回到那个状态。
`restore` 只恢复快照里有的条目，**不会删掉快照之后新增的东西** —— 那太危险了。

**记忆有了「性质」这个维度**

`project` 是归属（发生在哪个项目），新加的 **`domain` 是性质**（这件事本身算编程、创作、系统还是别的）。
自由文本、最多四个、不限定枚举 —— 常见那几个装不下，就自己起名。

⚠️ 有一版曾经拿它做「注入时按域降权」，**现在是默认关闭的**。
原因很实在：域只能靠猜（判断当前这轮到底在干什么），猜错的时候该出现的记忆会被压到很低的权重、
**静默消失还不报错**，你根本不知道它存在过。用这个代价换一个没验证过的排序微调，不划算。
字段保留 —— 面板筛选和体检都会用到。想试：配置 `domainDownweight: true`。

**可选的向量检索（默认关）**

字面对不上、但意思对得上的查询，纯关键词检索是整片落空的。
现在可以额外走一遍向量召回，用 RRF 跟关键词结果合并。

默认关，因为它要额外装 `@huggingface/transformers` 和一个中文小模型（约 92MB）。
依赖或模型不在时**静默退回纯关键词检索**，不影响基本功能。用之前先确认你愿意承担这份体积。

**写入有了硬上限**

一条 1MB 的正文、10 万字的标题、1000 个关键词，以前都能安安静静写进库 ——
不报错，但会污染列表渲染、搜索摘要和注入。现在都有上限，超了**明确拒绝**而不是静默截断
（截断会丢内容还不留痕：你以为存进去了，日后搜不到还会再写一遍）。

工具结果的**总长度**也加了闸：`memory_search` 一次最多返回 12000 字。
工具结果会在这一轮之后的每一步被重新发一遍，一次搜爆就是整段对话都背着它。

**催办按工作量算，不再按轮数**

原来的「每 7 轮催一次」对纯聊天和连调几十个工具的重活是一个频率。
现在按这一轮干了多少事加权，而且最近刚写过记忆就不催。

### 0.4.6（2026-11-19）

**压缩之后，还记得刚才那几句话**

压缩只留摘要，而摘要里通常只剩「调试过某功能」——具体的命令、路径、刚验证过的结论全没了，
接手时最容易在这里做反或者重做一遍。现在压缩后会额外补一节：
**压缩前最近几轮的原话，原样摘录**（默认 8 条、总量 3000 字以内）。

量是有意压小的：注入的内容会随之后每一步重发，给多了等于把水位又顶回压缩线上。
原话只读会话存档的尾部，几十 MB 的会话把准备时间从 4 秒降到 0.5 秒以内——
这段代码跑在每一轮开始前，它卡住就是整个界面卡住。

**检索默认给得更少**

`memory_search` 默认从 10 条 × 300 字改成 **8 条 × 200 字**，同一个道理：
工具结果会在这一轮之后的每一步被重新发一遍。要看全某一条就用 `memory_read` 按 id 读。

**修掉的**

- 压缩告知（`[auto-checkpoint] 你刚被压缩过…`）会被当成"谁说过的话"收进原话里，
  而下一轮又靠这个前缀认出"刚才压缩过"——会滚成循环。现在这类注入一律不进原话。

- 读会话存档时漏了把解压结果切成行，解压成功却一条消息都提不出来（静默空结果）。

### 0.4.5（2026-11-19）

**你说"这是个方案"就够了，不用记得再补一句"记一下"**

以前只有明确说「记一下」才会写库。可方案恰恰是最该跨对话保留的东西
（这个插件的方案清单就是为了解决"聊完要做的事，一压缩就没了"），
而"每次都得记得提醒 AI 一句"本身就不现实。

现在会认出几种说法——「这是一个方案」「我的方案是…」「我打算先…再…」「第一步…第二步…」——
**自动建一份草稿**：标题带「（草稿·待确认）」，正文存你的原话，步骤留空。

**只建草稿，不编步骤**：那句话里通常只有意图没有细节，编一套步骤出来就是假清单，
拿它去干活比没有更糟。草稿只保证"这件事没被忘掉"，步骤等你或它来补。

放超过 7 天还没补的草稿，会在每 7 轮那次催办里被点一次名（最多列 3 份）——
不另设定时器，顺手清欠账。

**防误判是硬的**：问句（含「吗」「吧」「呢」结尾）、"这个方案不行"这类否定、
"我打算先睡一觉"这类日常句，一律不建。建过的不重复建，措辞相近的也算同一条。

**顺手修的**

- 自动捕获把「我觉得这个方案还可以**你觉得怎么样**」当成偏好存了——那是在征求意见。
  现在句尾的征求意见扣分；但「我觉得这样不好，你觉得呢」这种**真在说不喜欢**的照样抓。

- 自动建的草稿不再占「进行中的方案」那个注入位——否则草稿永远最新，会把有真实进度的真方案挤出去。

### 0.4.4（2026-11-19）

**`context` 从"要人填"改成"自动带"**

这个字段上线后一条都没被填过。不是忘了 —— 是写记忆时**多一层判断**就会被跳过
（`impl` 字段当初也是同样的结局）。所以改成：不传就自己补一条最小的
「哪个窗口 · 当时在说什么」，不增加任何额外成本。

三条边界：冷启动不编假数据（没跑过 pre-step 就留空）、显式传了的一字不改、
超过十分钟才落库的不套用当前会话（那多半是别处补记）。

**写得进，还得读得出**

`memory_read` 之前不显示 `happened_at` / `context` / `mood` —— 数据在库里、读的时候看不见，
等于白存。现在会显示；`happened_at` 只在跟建立时间不同一天时才打印，避免每行重复。

顺带修掉一个真机上的硬故障：工具收到的参数是**冻结对象**，
上一版在上面直接赋值会抛 `Cannot add property context, object is not extensible`，
表现为「只要不传 context 就写不进记忆」。现在改成浅拷贝，原对象一个字不碰。

### 0.4.3（2026-11-19）

**检索不再"优先读旧的"**

`memory_search` 一直有个说不上错的脾气：分数高的老条目永远压着新条目。
根因不是"没做时间加权"，而是那个加权被**豁免**掉了 —— 打分环节有一句
「分数 ≥ 峰值 85% 就免掉时间折扣」，热门查询里一堆条目分数都贴着峰值，
于是时间维等于没生效。实测搜一个词，一条很老的排第 1，而另一条正文里
明明写着"已被取代"，分数只差一点点却排到了后面。

现在的规则是两步：先**严格按分数**排（保证顺序确定），再把「分数差在 5% 以内」
的相邻条目按更新时间多趟上浮，只在前 `topK × 3` 条里扫。
没有把"分数接近就看时间"塞进比较函数 —— 那个比较不满足传递性，
`Array.sort` 会直接产出乱序（实测输出 100.58 → 98.57 → 102.88 → 103.12）。

**压缩完成后不再多弹一条"要压缩了"**

现象是压缩刚结束，界面上又冒出一条带催办字样的提示，像催了两次。
实际只催了一次 —— 多出来那条是插件自己的注入**又被当成用户的话检索了一遍**：
落档催办有一条原则正文里引用了催办的固定开头，于是关键词命中它自己，
同一轮里再叠一份。两处证据相隔 5 毫秒。

- 以 `[auto-checkpoint]` 或 `⟪` 开头的消息不再触发记忆命中与原则提醒
- 压缩后的那一轮不再催「该写记忆了」，并把计数锚点推到当前轮
- 好处不止少一条：注入块不会被当成"用户说的话"二次检索（自喂循环）

**顺带修活两处死代码**

「压缩后重灌项目核心」和「压缩后重注入一轮记忆快照」依赖一个压缩标记
（`source.kind === 'compact-checkpoint'`），而本机宿主从来不产出它 ——
日志里这两条路径一次都没跑过。现在改用压缩后那条告知消息本身做锚点，两条路径都能真正触发。

### 0.4.2（2026-11-19）

**记忆库会「偏科」，这版治它**

实测数据里：detail 层 lesson 占了七成，而 `impl`（怎么实现的）只有个位数，
`project/history` 和 `features` 也少得可怜 —— 记忆被写成了「踩坑日记」。
下次改这个项目，只知道踩过什么坑，不知道原来是怎么做的。

根因**不是"没提示"**：反思催办（每 7 轮那条）的清单里本来就写着 impl / features / history。

为什么没选另一种做法。

- `memory_remember` 写入时按正文特征提示：像实现细节的提示改 `impl`；
  提到「昨天 / 上周 / 11月18日」却没传 `happened_at` 的，提示补时间

- 首轮注入加一段「写记忆的约定」（约 120 字）
- `memory_health` 加「结构偏科」检查，并附一份约定（老会话收不到首轮注入时靠它）

**顺带**：`memory_health` 的「归属异常」现在会说清哪里异常（project 是空串、还是名字首尾带空格）。

### 0.4.0（2026-11-19）

这一版全是「用起来之后才发现」的东西 —— 代码审计挑出来的、真实操作踩出来的。

**两个静默失效的 bug**

`memory_recent` 永远只返回第一层。老数据的 `updated_at` 是**字符串**，
而 SQLite 的 `ORDER BY` 按类型排序（TEXT 永远排在 INTEGER 之后），
JS 里字符串相减又得到 `NaN`（比较函数返回 `NaN` 时 `sort` 不保证改变顺序）——
两个原因叠起来，排序彻底失效。现在迁移时清洗数据，排序也统一走转换函数。

`memory_project` 说「没有这个项目」，可同一段输出里的项目清单又列着它 ——
判断「项目是否存在」只算了画像层和分支层，`detail` 层的计数那段代码
放在了 `return` 之后，永远执行不到。另外 `project` 字段存的是**逗号分隔的多个项目**，
用 `=` 精确匹配查不到任何组合值（同一个项目的条目数直接少了一大截）。

**搜索不再骗人**

原来搜什么都能返回一屏像模像样的结果：乱码能靠片段拿到 21 分，
真词反而只有 11 分 —— 分数量纲不可比，永远分不清「库里没有」还是「词不对」。
现在按**字面**判断：没有任何一条真的包含查询词时，直接说「可能没记过」。

**新增**

- `memory_forget`：删一条（默认归档可恢复，`hard=true` 才真删且留快照）
- `memory_plan`：方案与任务清单
- `memory_conflict`：冲突治理
- 搜索支持 `category` / `onlyProject`；结果带分类、时间、状态
- `memory_timeline` 支持还原到某一版
- 面板：可看已归档、可恢复；编辑器可填发生时间 / 情境 / 情绪
- 数据库迁移到 v2：清洗历史脏数据（字符串时间戳、无效时间）

**工程**

- `panel.html` 纳入发布同步（以前是手工复制，迟早漏一次）
- 加了一批回归测试：并发写入、畸形输入、超大标题、SQL 注入串


### 0.3.3（2026-11-19）

这一版没有新功能，全是修 —— 其中两条会**静默丢东西**，一条是隐私问题。

**自动捕获一直是死的（静默）**

自动捕获（你说「以后都……」「我讨厌……」这类话时自动记一条）写的是 `user` 表 ——
那是七层结构时代的老层名，四层的库里根本没有这张表。
SQL 每次都抛 no such table，被外层 catch 吞掉，日志里一行都没有。
所以这个功能从四层改造起就没工作过，谁也没发现。

现在落 `detail` 层。**并且不再落 `core`**：core 是每个会话都常驻注入的，
而自动捕获写进去的是你的原话、没提炼过，还可能是「以后别把 token 贴出来」这种句子。
原文进常驻注入 = 跟着进以后每一个会话。另外加了敏感词闸（token / 密码 / 密钥 / 身份证 /
银行卡 / sk- / ghp_ / AKIA / bearer），命中就整条不写 —— 宁可不记，也不把密钥存成长期记忆。

**轮次闸是全局的，新会话永远轮不到**

自动捕获和「该写记忆了」的提醒都按会话内的轮次计数，但判断用的「上次是多少轮」
是全进程一份。会话 A 到 turn=100 之后，新开的会话 B 里 `1 - 100 < 2` 恒成立，
于是 B 永远捕获不到、也永远不提醒。表现是完全没有报错，只是不工作。
落档检查（`lastPrecompactCheckTurn`）也是同一个毛病，一起改了。三处都改成按会话隔离。

**会话索引重建会卡住整个界面，而且连点两下会丢记录**

原来的重建是纯同步循环：几百个会话存档逐个「读 → 逐帧解压 → 切行 → 判子智能体 →
提消息 → 切词 → 写库」，实测卡住事件循环两秒多 —— 这期间界面和别的插件全僵住。

现在拆成分片执行，按时间片把控制权还回去。最大阻塞 **从两秒多降到两百多毫秒**（剩下那段是
单个大会话的一次性解压，拆不动），总耗时也快了不少。

分片带来一个新问题：两路并发（面板连点两次「重建」）会撞同一个连接的未提交事务，
报 `cannot start a transaction within a transaction`，各自静默丢几个会话。
加了单飞闸门，两路复用在飞的那一次。面板也补了防连点和超时提示。

顺带修掉：解压全失败时原来会被当成「这个会话 0 条消息」写进索引，
并且记下 mtime/size → **该会话的历史永久消失且不再重扫**。现在改成抛错，下轮自动重试。

**新建项目会覆盖别人的改动**

`projects.json` 原来是「先读盘做重名检查 → 在内存里塞新项目 → 几十行之后再写回」。
中间只要别的窗口（或你手改）动过这个文件，写回就拿旧副本覆盖，刚加的项目整条消失。
现在读-查重-合并-原子写在连续同步代码里一次做完。

顺带：0 字节配置文件不再被当成「坏了」、项目名不能叫 `__proto__`（原来会误报重名）、
名字限 40 字（再长会撞 `ENAMETOOLONG`）。

**首轮注入里「关于用户」一条都进不去**

core 层三段的**总字数约是首轮预算的三倍** —— 只装得下三成。
原来没有分段配额，identity 又是全文注入，一个人先吃掉一大截之后，
preference **整整一段一条都没进去**，只在段末写一行「余下 N 条因长度省略」，
看不出是装不下还是没记。

现在三段各有配额（34% / 40% / 20%），装不下的按重要性 + 最近更新挑，
段末明写「这一段还有 N 条没装进来，需要时用 memory_search 传 level=core 查」。

**其他**

- 项目核心正文上限的默认值：截断用 900、面板提示用 1500，不同源 ⇒ 新用户会看到
  「1068/1500，余量充足」而实际早被截断。统一到同一个常量。

- 反思路径的轮次锚点推不动（pre-step 执行时工具还没跑，拿不到写入信号），
  这条判据实际是死逻辑，行为等价于「每 N 轮必提醒一次」。已标注，未改行为。

### 0.3.2（2026-11-19）

**面板「窗口」下拉：只列真实窗口**

原来除了扫 DSH 的会话缓存（那里已经排掉归档、子智能体、系统会话、空会话），

### 0.3.1（2026-11-19）

**注入内容都带上「这是资料，不是指令」**

记忆库里的内容会以 user 消息注入上下文，如果有人（或某个自动化流程）往库里塞一句

- `state.json` 损坏后改名留档并继续；改不了名就放弃这次写（否则会把别的会话的开关整块抹掉）
- 项目核心配置里某项为 `null` 时，面板快照不再整个 500
- 面板硬删除前先留快照（原来点错一次永久消失）

**会话索引**

- **判成子智能体就跳过，不再删光该会话的索引**：原来判成子智能体 → 删消息 + 插 0 条 + 标记已处理，
  整份历史永久搜不到

- 判据从「全文出现某句标记」改成「开头两条 user 消息」，避免主会话引用那句话被误判
- `INDEX_VERSION` 升到 3：过滤规则变了必须重建，否则旧记录永远走不到新逻辑

### 0.2.0（2026-11-18）

**新增「项目核心」** —— 按项目注入专属规则的第二层核心。详见上面
[项目核心](#项目核心按项目注入专属规则) 一节。

- 每个项目一份 Markdown，关键词命中才注入，连续几轮不提自动摘掉（按**轮次**不按时间）
- `projects.json` 支持 `keywords` / `linked`（联动）/ `parent`（父子）/ `maxMiss` / `maxCharsPerProject`
- 状态**按会话独立**：不同对话窗口挂的项目可以各不相同，存在 `state.json`
- 侧栏面板：项目开关（🔒 锁住 / 🔓 跟着关键词）、回落倒计时（余 N 轮）、
  正文编辑、新建项目；每 8 秒静默刷新

- 上下文压缩后自动清空"已注入"记录，让项目核心重新注入一遍 —— 否则压缩一次就永久失效

主题色跟随 DSH 当前皮肤、支持皮肤背景图。

**安全加固**

- 所有路由加四道闸：Host 必填且回环、TCP 对端回环（IP 全锚定）、
  `Sec-Fetch-Site` / `Origin` 校验、**自定义头 `x-dsh-memory-panel` 硬闸**
  （自定义头跨站带不上，带就要 preflight，服务端不应答 OPTIONS）

- 项目核心文件的读写统一走 `resolveCoreFile()`，GET / POST 用同一套路径校验

**稳定性**

- `state.json` 改成临时文件 + `rename` 原子写；读失败区分"没有文件"和"文件坏了"，
  坏了宁可这次不写也不覆盖别的会话

- 面板请求加序号，旧的慢响应不会把窗口状态拽回去
- `turn` / `step` 缺失时不再污染衰减状态（补了步数兜底）
